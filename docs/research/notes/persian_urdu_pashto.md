## Q1. Persian (Farsi/Dari): formal romanization standards, with full mapping tables (UN 2012, BGN/PCGN 1958, ALA-LC, EI/Iranica, DMG, ICAO)

### Takeaway
Persian has at least six live systems. They agree on the easy letters and disagree in three places: (a) the Arabic "homophone" letters (ث ص / ذ ز ض ظ / ت ط / ح ه), which only the diacritic systems tell apart; (b) the short vowels (UN/BGN/EI/DMG use a-e-o, ALA-LC uses a-i-u); (c) غ/ق, which UN 2012 merges as **q**, while everyone else writes غ = gh/ġ/ḡ and ق = q. Practical English spellings come out roughly as "BGN/PCGN with the diacritics stripped, plus Persian vowels". ICAO's reversible MRZ scheme (XKK, XYA…) is informative only, and Persian-script passport issuers do not appear to use it (see Gaps).

### Cited Findings

**Status and provenance**
- The current UN-recommended Persian system was approved in 2012 (resolution X/8). It is based on a "broad transcription" developed in Iran since 1988 and officially approved there in 2003. It replaced the 1967 UN system (I/13), which was based on Iran's 1966 system. Iran implements the 2012 system in its national geographical names database and on some maps — [UNGEGN WGRS Persian](https://www.eki.ee/wgrs/rom1_fa.pdf)
- The UN 2012 system "is not fully reversible as it is based on pronunciation", so different letters with the same sound are romanized the same way — [UNGEGN WGRS Persian](https://www.eki.ee/wgrs/rom1_fa.pdf)
- The previous Iranian national system (1966), approved by the UN in 1967, "coincid[es] with that of BGN/PCGN 1958 (revised 2007)" — [UNGEGN WGRS Persian](https://www.eki.ee/wgrs/rom1_fa.pdf)
- BGN/PCGN Persian was adopted by BGN in 1946 and PCGN in 1958. The current document was "checked for validity and accuracy – December 2019". Afghanistan names (Dari and Pashto) use the separate "BGN/PCGN National System of Romanization for Afghanistan (2007)" instead — [BGN/PCGN Persian](https://assets.publishing.service.gov.uk/media/5e1eeaafe5274a4f0f57553a/ROMANIZATION_OF_PERSIAN.pdf)
- The US NGA's Iran country policy (March 2024 update) says Persian names are romanized with the 1958 BGN/PCGN system — [NGA Iran Country Policy, search-result snippet](https://geonames.nga.mil/geonames/GNSSearch/GNSDocs/policies/Iran_Country_Policy_Webversion_Mar2024_Update.pdf) (not fetched in full)
- The ALA-LC Persian table is the "2012 version" (earlier versions 2011 and 1997). For supplying vowels, LC consults M. Muʼīn, *Farhang-i Fārsī-i mutavassit* — [ALA-LC Persian](https://www.loc.gov/catdir/cpso/romanization/persian.pdf)
- ISO 233-3:1999 (simplified Persian transliteration) differs from UN 2012 as follows: ā=â, ḥ (ح), ġ (غ), s̱ (ث), ṣ (ص), ṭ (ط), ḵ (خ), ẕ (ذ), ż (ض), ẓ (ظ), ‘ (ع). UNGEGN notes that the ISO standard "obviously contains some typographic errors" — [UNGEGN WGRS Persian](https://www.eki.ee/wgrs/rom1_fa.pdf)

**BGN/PCGN Persian special rules (directly relevant to names)** — [BGN/PCGN Persian](https://assets.publishing.service.gov.uk/media/5e1eeaafe5274a4f0f57553a/ROMANIZATION_OF_PERSIAN.pdf)
- Names ending in Allāh are written as one word with a → o: ‘Abdollāh. A standalone الله is written Allāh. The dagger alef is romanized ā.
- -ābād is always joined to the preceding word (Raḩmatābād). Plural -hā/-ān is joined.
- Persian derivational endings such as -vand, and Turkic endings -lar, -lī, -lū, -ī, -ū, -sī, -sū, are written together with the preceding word (relevant to surnames like -lou/-loo).
- خو followed by ا or ی (or pointed with damma) → khv (Khvājeh). The v is silent or weak.
- The sequences کھ زھ سھ گھ may be written k·h, z·h, s·h, g·h (middle dot U+00B7) to avoid confusion with the digraphs kh/zh/sh/gh.
- Word division follows the Persian script, except for the false-generic and suffix rules.
- Vowel characters 5, 7, 8, 9, 10 (á, ī, ū, ey, ow) "may be pointed in two different ways". Initial alef + ی/و gives Ī/Ū (Īrānshahr).
- Inconsistency in the standard itself: BGN lists the Persian ی with Unicode value **0649** (alef maksura), not U+06CC.

**ALA-LC Persian rules relevant to ZWNJ/compounds** — [ALA-LC Persian](https://www.loc.gov/catdir/cpso/romanization/persian.pdf)
- When an affix is written *separately* in Persian (i.e., with ZWNJ or a space), it is separated by a prime ʹ: "Kāẓimʹzādah" (کاظم‌زاده) vs "Kāẓimzādah" (کاظمزاده); mīʹravam vs mīravam; khānahʹhā.
- Compound personal names are an exception. "Ghulām ʻAlī" is written that way whether the script has غلامعلی or غلام علی; likewise "Shāh Jahān", "Ibn Abī Ṭālib".
- The prime is also used to separate two letters that could otherwise be read as a digraph (marzʹhā).

**ICAO Doc 9303 (passport) treatment of Arabic-script names** — [ICAO Doc 9303-3](https://www.icao.int/sites/default/files/publications/DocSeries/9303_p3_cons_en.pdf)
- When a name is in a non-Latin script, a Latin "transliteration" in the VIZ is mandatory (Doc 9303-3 §3.1/3.4). ICAO notes that for Arabic script this "is commonly a phonetic equivalent and should be more correctly termed a 'transcription'", and that the choice of scheme "is at the discretion of the issuing State".
- Appendix B lists 16 "applied variants" of محمد: Muhammad, Moohammad, Moohamad, Mohammad, Mohamad, Muhamad, Mohamed, Mohammed, Mohemmed, Muhemmed, Muhamed, Muhammed, Moohammed, Mouhammed (plus duplicates in the list). It adds that "in some countries it is common to replace the final 'd' with 't'", giving 32 variants.
- Appendix B, Persian example: الرازي is spelled with the Persian yeh in Farsi, and ICAO deliberately used the Arabic yeh.
- §6 table C gives a *reversible* MRZ transliteration with X-prefixed codes for non-ASCII letters (see Table P1 and the Urdu/Pashto tables). Shadda doubles the code (عباس → EBBAS). The MRZ name field is 39 positions using only A–Z and <.

### Inferences
- **Engine design:** implement Persian as a phoneme layer (letter + context → abstract phoneme, e.g. `ZAAL`, `ZE`, `ZAD`, `ZA` kept separate) followed by per-standard output tables. Only ALA-LC, BGN/PCGN, EI, DMG and ICAO keep the homophone letters apart. UN 2012 and practical English collapse them.
- **Vowel inference is the hard part.** Unpointed Persian has no short vowels, and every standard assumes a dictionary (LC names Muʼīn; BGN says "a reference source may sometimes be required"). A name package needs a **lexicon of vocalized names** (e.g. محمد→Mohammad, حسین→Hossein, رضا→Reza, مهدی→Mehdi), with rule-based fallback only for out-of-vocabulary words.
- **Practical/English profile ("Iran style")** = UN 2012/BGN skeleton with: ā→a, ī→i, ū→u|ou|oo, x/kh→kh, č→ch, š→sh, ž→zh, غ and ق→gh (q as a variant), ح/ه→h, ع→drop, final silent ه→-eh (BGN style, very common in surnames: Zadeh) with -e/-ah as variants, ezafe→-e/-ye joined or dropped, Allāh compounds joined with -ollah|-ollah|-olah|-ullah.
- **"Afghan/Dari style"** profile: و→w as a consonant variant (BGN Pashto/Afghan systems use w), short u/i retained more often (Gul, Mohammad/Muhammad), majhul ē/ō vowels possible (EI Dari values ō/ē), ق→q.
- ICAO MRZ X-codes (XKK, XYA, XDO…) are useful as a **lossless canonical key** for de-duplication, even though issuing states don't print them.

### Gaps
- iranicaonline.org returned HTTP 403, so the EI 2012 values come from Wikipedia's comparison table and were not checked against Iranica's own guidelines page. In particular, the treatment of final silent ه (Iranica is often cited as writing -a, e.g. "nāma") and the damma value are unverified.
- The DMG 1969 column also comes from Wikipedia only.
- No primary document was found for Iran's ISIRI national transliteration standard for personal names (if one exists).

## Q2. Persian/Dari in practice: English spellings, vowel conventions, surnames with suffixes, Afghan names and passport practice

### Takeaway
Real-world Iranian and Afghan Latin spellings are phonetic and unstandardized. Iranian spellings follow Persian pronunciation (a/e/o short vowels, gh for both غ and ق, "ou/oo" for ū, -eh for final silent h, "ss" for intervocalic s as in Hossein). Afghan spellings scatter more (Massoud/Masoud/Mas'ud), drop or move components (M. Zaman Naderi), and treat honorific second elements (Khan, Jan, Gul) as surnames in the West. Persian surnames are built from fixed suffixes (-i, -ian, -zadeh, -pour, -nejad/-nezhad, -far, -nia, -lou, -bakhsh, -dad, -ollah), which are often joined across a ZWNJ in the script and written joined, hyphenated or spaced in Latin.

### Cited Findings
- Persian (Fingilish/Penglish) informal letter mapping as listed by Wikipedia: آ/ا → a, â; ث → s; چ → ch, č; ح → h; خ → kh, x; ذ ز ض ظ → z; ژ → zh, ž; ش → sh, š; ص → s; ط → t; ع/ء → a, ə; **غ → gh, q; ق → gh, q**; و → o, u, v, w; ی → i, y — [Wikipedia: Romanization of Persian](https://en.wikipedia.org/wiki/Romanization_of_Persian)
- "In Persian language contexts, the transliterations Ḥosayn, Hosayn, or Hossein are sometimes used" for حسین — [Wikipedia: Hussein](https://en.wikipedia.org/wiki/Hussein)
- "Reza" is the Persian variant of the Arabic name Rida — [Wikipedia: Reza](https://en.wikipedia.org/wiki/Reza)
- Persian name structure: given name plus surname (nām-e khānevādegi). Surnames became mandatory under Reza Shah (law after a 1919 act); "Ahmadi" became the most popular surname. Toponymic surnames are formed with -i (Tehrani, Tabrizi, Shirazi, Esfahani, Ghomi, Yazdi, Ardabili…) — [Wikipedia: Persian name](https://en.wikipedia.org/wiki/Persian_name)
- Persian surname suffixes listed by Wikipedia: **-i** (most common; adjectival), **-ian** (plural + -an; Shaheenian), **-an**, **-pour** ("descendant of"), **-zad / -zadeh** ("descendant of"), **-nezhad / -nejad** ("of race/clan"), **-nia**, **-far**, **-bakhsh** ("granted by"), **-dad** ("given by"), **-ollah** ("of Allah"), **-loo / -lou** ("from"). Prefixes and titles: Haji, Karbalaei, Mashhadi (→ Mashti/Mash), Mir, Seyed, Agha, Ostad, Mollah — [Wikipedia: Persian name](https://en.wikipedia.org/wiki/Persian_name)
- Example of the -zadeh surname type written split: "Moazenzadeh" vs the father's "Moazzen Zadeh Ardabili" (also showing the zz/z gemination variation) — [Wikipedia: Persian name](https://en.wikipedia.org/wiki/Persian_name)
- Official forms of Seyyed in the standards: BGN romanizes سید as **Seyyed** (doubled y for consonantal shadda) — [BGN/PCGN Persian](https://assets.publishing.service.gov.uk/media/5e1eeaafe5274a4f0f57553a/ROMANIZATION_OF_PERSIAN.pdf); ALA-LC (Urdu) gives **sayyid** — [ALA-LC Urdu](https://www.loc.gov/catdir/cpso/romanization/urdu.pdf); Wikipedia's Persian-name article uses "Seyed" — [Wikipedia: Persian name](https://en.wikipedia.org/wiki/Persian_name)
- Afghan names: personal names are generally not divided into first and family names. Male names are often two-part compounds (Mohammad Zaman, Ghulam Hazrat, Abdul Ali, Din Mohammad). Women's names are usually single (Fereyba, Laila, Roya), occasionally two-part (Gol Khanom) — [Wikipedia: Afghan name](https://en.wikipedia.org/wiki/Afghan_name)
- Afghan surname suffixes: -ai/-i (Karzai, Kohistani, Hussaini), -zai/-zoy (Ghilzai, Popalzai, Yusufzai), -khel/-khil (Suleimankhel, Omarkhil), -gul (Gulbaz), -ullah (Rahmatullah, Hafizullah), -uddin (Shamsuddin, Ghawsuddin), -zada/-zadah (Khanzada, Shahzada), -bakhsh, -dad (Baridad). Honorifics: Khan (men), Jan (men and women: Khalil Jan, Sharifa Jan), Agha, Mullah, Mawlawi, Ustad, Ghazi, Sayyid, Sardar, Khwaja, Akhund, Shah. Gender-neutral names: Gul, Lal, Sultan, Taj, Shaista — [Wikipedia: Afghan name](https://en.wikipedia.org/wiki/Afghan_name)
- Afghan transcription practice: "there is no orthographic standardization… many discrepancies in transcription of Afghan names into English, especially from Pashto". The second component (Khan in "Gul Khan") is generally treated as a last name in the West. مسعود is "variously transcribed as Massoud, Masoud, or Mas'ud". Spacing varies (Miakhel vs Mia Khel). A name like "Mohamad Zaman Naderi" may be written "M. Zaman Naderi" or "Zaman M. Naderi" — [Wikipedia: Afghan name](https://en.wikipedia.org/wiki/Afghan_name)
- Afghan given-name romanizations in a Wikipedia list (real-world style, not a standard): Qader (قادر), Rasol (رسول, o for ū), Aimal (اېمل), Daud or Dawud (داوود), Hafez, Humayun, Omid, Paiman, Rangeen (ee for ī), Sohrab, Shahpur, Wais, Zalmay (زلمې); female: Freshta/Farishta, Fawzia, Kawtara/Kontara, Spogmay/Spozhmay, Forozan, Malala/Malalai, Zareena, Zaituna — [Wikipedia: Afghan name](https://en.wikipedia.org/wiki/Afghan_name)

### Inferences
- **Vowel conventions to encode (Persian Iran style → variants):**
  - damma o ⇄ u: Mohammad/Muhammad, Hossein/Hussein, Gol/Gul (Iran o; Afghan, Arabic and Urdu u).
  - kasra e ⇄ i: Hekmat/Hikmat, Esmail/Ismail, Hossein/Husayn (the second syllable).
  - fatha a ⇄ e next to h, ʿ or ḥ: Persian pronunciation often gives e (Mehdi for مهدی; Arabic Mahdi). Pakistani English shows the same "Rehman" for رحمان (attested in Q3). Treat a⇄e as a high-probability variant when the next consonant is ح/ه/ع.
  - ū: u / ou / oo / o (Mahmoud, Masoud, Davoud, Daud, Rasol, Forozan).
  - ī: i / ee / y-final (Ali, Rangeen, Zareena).
  - diphthong ey: ey / ei / ay / ai (Hossein, Husayn, Meymand, Maidan).
  - ow: ow / o / au / ou (Khosrow/Khosro, Nowruz/Norouz).
  - final silent ه: -eh / -e / -ah / -a / ∅ (Zadeh/Zade/Zada, Fatemeh/Fateme/Fatima).
- **Gemination:** shadda is unwritten in normal text, so emit both single and double (Mohammad/Mohamad, Hossein/Hosein, Seyyed/Seyed/Sayed/Syed, Abbas/Abas).
- **Surname segmentation:** a suffix in {zadeh, zade, zada, pour, poor, nejad, nezhad, nejhad, nia, far, lou, loo, bakhsh, dad, ollah, ian, i} attaches to a stem. Generate joined (Ahmadinejad), hyphenated (Ahmadi-Nejad) and spaced (Ahmadi Nejad) forms, and for matching compare on a key with spaces, hyphens, ZWNJ and apostrophes removed. ZWNJ in the source (احمدی‌نژاد) is evidence that the formal romanization would use a prime (ALA-LC) or join (BGN, by analogy with its suffix rule).
- **Afghan compound given names** (Mohammad Zaman, Abdul Ali, Din Mohammad, Gul Khan): the matcher should allow component reordering, initial-abbreviation (M.) and the "Khan/Jan/Gul as surname" reading.

### Gaps
- **Iranian passport practice could not be documented from primary sources.** No NAJA/Police+10 or passport-office rule for the Latin name spelling was found (a Persian-language search returned nothing relevant). Wikipedia's Iranian passport article only says captions are bilingual (Persian/English). Whether the Latin spelling is applicant-chosen or system-generated, and which convention it follows, is unconfirmed.
- No primary Afghan passport/e-Tazkira rule for Latin spellings was found (a search turned up only general e-Tazkira descriptions).
- Frequency data for variants (e.g., Hossein vs Hosein vs Hosain among Iranian passport holders) was not found.
- The Mehdi/Mahdi pattern is not covered by a fetched source; the general a→e shift is inferred from Persian pronunciation and the Pakistani "Rehman" evidence.

## Q3. Urdu: ALA-LC, BGN/PCGN (Hunterian-based), UN 1972; extra letters, aspirates; Pakistani name structure and NADRA/passport practice

### Takeaway
Three formal systems exist. **ALA-LC 2013** is a library standard: ٹ ṭ, ڈ ḍ, ڑ ṛ, ں ṉ, چ c (!), aspirates written with h, majhul vowels e/o, and ai/au. **BGN/PCGN 2007** is Hunterian with diacritics: ṭ ḍ ṛ, ñ for ں, w for و, chh. The **UN 1972** system is reported as unused. Pakistan officially uses Hunterian for place names. Personal names in Pakistan are written in English by applicants and fixed through NADRA's CNIC, which the passport must match. Real-world spellings are diacritic-free and Hunterian-like (Muhammad, Rehman, Hussain, Syed, Ullah/Ud Din split or joined).

- The UN Urdu system was approved in 1972 (II/11) and amended in 1977 (III/12). "There is no evidence of the use of the system either in Pakistan, India or in international cartographic products. ## Q4. Pashto: extra letters and romanization standards/practice

### Takeaway
Pashto has two library/geographic standards: **ALA-LC Pushto 2013** (ṭ ḍ ṛ ṇ ṡ ż ẓh ṣh, ạy) and **BGN/PCGN 1968 / 2017 revision** (ṯ ḏ ṟ ṉ ts dz z͟h s͟h, ē, ê, êy, w). - Final ی/ې/ۍ ambiguity: much Pashto text is typed on Persian or Arabic keyboards where ۍ, ې and ئ get replaced with ی/ي/ى. Normalization for matching should fold them (keep the original for formal romanization).

## Q5. Bengali (Bangladesh): Muslim name romanization — variant patterns

### Takeaway
Bangladeshi Muslim names are romanized from Bengali script in an ad hoc, English-phonetic way, not with a formal Bengali transliteration. The key matching phenomena are: the Md./MD./Mohammad prefix (and the female Mst./Mosammat); Bengali vowel colouring of Arabic names (o for short a: Hossain, Muhammod, Mosammat); surname-like titles (Chowdhury, Sheikh/SK, Sarkar, Talukder, Bhuiyan, Miah, Khan); and female second names (Begum, Khatun, Akter/Akhter/Akhtar, Islam/Rahman as male "surnames"). Passports print field values in English only. The passport office has tried to ban abbreviations, but NID records still contain them.

### Cited Findings
- "Muhammad (মোহাম্মদ), also spelled Mohammed, Muhammed, Mohamed, Mohammad, or Muhammod, is a common prefix used before the name of many Muslim males", often shortened to মোঃ ("Md." or "MD.") — [Wikipedia: Bengali name](https://en.wikipedia.org/wiki/Bengali_name)
- Bengali Muslim surnames and titles include Chowdhury, Dewan, Sheikh, Sarkar, Khan, Talukdar, Bhuiyan, Miah, Mridha, Syed, Kazi, Fakir, Molla, Gazi, Howlader, Mandal, Mirza — [Wikipedia: Bengali name](https://en.wikipedia.org/wiki/Bengali_name) (via a WebFetch summary of the page)
- Common abbreviations: Mohammad → "Md"/"MD", Sheikh → "SK", Mosammat → "MST". Bangladesh's passport office "once issued a notice prohibiting the use of abbreviated names", but because the notice was not integrated into the e-passport system, people whose NIDs carry "Md", "MD", "SK" or "MST" had trouble getting passports. Typical full names: "Mohammad Kabirul Islam", "Mosammat Shukjan Khatun". Users themselves often treat the religious prefix as ceremonial — [The Financial Express (Dhaka), 26 Oct 2021, op-ed by Prof. Mohammad Towhidul Islam](https://thefinancialexpress.com.bd/views/opinions/peoples-names-confusion-that-needs-to-be-shed-1635257108)
- Bangladeshi e-passports (since January 2020) print field names in Bengali and English, but "field values [are] written in English only" — [Wikipedia: Bangladeshi passport](https://en.wikipedia.org/wiki/Bangladeshi_passport)
- Hossain/Hussain are the Indo-Aryan-language transliterations of حسين — [Wikipedia: Hussein](https://en.wikipedia.org/wiki/Hussein)
- Chowdhury is the most common English spelling in Bangladesh; full variant list in Q3 — [Wikipedia: Chowdhury](https://en.wikipedia.org/wiki/Chowdhury)
- The ALA-LC Bengali table exists at LoC, but its text could not be extracted (custom glyph ligatures) — [ALA-LC Bengali](https://www.loc.gov/catdir/cpso/romanization/bengali.pdf)

### Inferences
- **Bangladeshi variant generator (pattern-level):**
  - Prefix: Mohammad | Muhammad | Mohammed | Muhammod | Md | Md. | MD | Mohd → collapse to a single canonical prefix token that may be dropped. Female: Mosammat | Mosammet | Musammat | Most. | Mst | Mst. → canonical, droppable.
  - Bengali inherent-vowel effect: Arabic short a/u ↔ o (Hossain, Hossen, Hussain, Husain; Mohammod; Rohman/Rahman; Mostafa/Mustafa; Golam/Ghulam; Abul/Abdul).
  - Aspiration and "kh" variation: Akter | Akhter | Akhtar | Aktar; Khatun | Khatoon.
  - -uddin | -udin | Uddin | Uddeen (Salahuddin), and -ul/-ur splitting (Mizanur Rahman, Habibur Rahman, Ziaur Rahman).
  - Titles as surnames: Chowdhury, Sheikh/SK/Shaikh, Miah/Mia/Mian, Bhuiyan/Bhuiya/Bhuyan, Talukder/Talukdar, Sarkar/Sarker, Howlader/Hawlader, Molla/Mollah/Mullah, Kazi/Qazi.
  - Female second elements Begum, Khatun, Akter, Nesa/Nessa/Nisa, Banu/Bano act like surnames on documents.
- Because names are written in Bengali script (not Perso-Arabic), the package should not try full Bengali→Latin transliteration for this use case. It should model Bangladeshi romanizations as a **variant profile over the canonical Arabic-origin name** (Hossain ← حسين).

### Gaps
- The text of the Bangladesh passport-office notice banning abbreviations (date, number) was not found. The only source is the 2021 op-ed.
- No current (2025–2026) DIP or Election Commission (NID) rule on English name spelling was found.
- The "Hossen" variant and the vowel-colouring patterns above are standard observations but have no source cited here; treat them as inferences.

## Q6. Malay/Indonesian (Latin-script) practice for Arabic-origin names

### Takeaway
Malaysian, Singaporean and Bruneian names are already in Latin script, but the Arabic elements vary heavily: Muhammad/Mohamad/Mohammad/Mohamed and the abbreviations Mohd./Muhd./Md./M.; bin/binti with B./Bt./Bte.; Nur/Nurul/Noor/Nor; Abdul/Abd. Malaysia's NRD (JPN) has banned new registrations using "Mohd"/"Abd" (spell out Mohamad/Muhamad/Muhammad and Abdul) and caps names at 80 characters including spaces. Older IDs still carry abbreviations, so matching must expand them. Indonesia has no consensus transliteration and adds Javanese/Betawi phonological adaptations plus pre-1972 spellings (oe/dj/tj).

### Cited Findings
- Malay patronymics use "bin" (son of) and "binti" (daughter of) plus the father's personal name. These are sometimes reduced to **B.** (men) or **Bt., Bte.** or **Bint.** (women) — [Wikipedia: Malay names](https://en.wikipedia.org/wiki/Malay_names)
- Common first elements: "Muhammad/Mohammad/Mohammed (often abbreviated to Muhd., Mohd., Md. or simply M.)". Female: "Nur/Nurul/Noor/Nor" and "Siti/Ct". "Abdul" must be followed by one of the names of God (Abdul Haqq) — [Wikipedia: Malay names](https://en.wikipedia.org/wiki/Malay_names)
- Hereditary titles (Tengku, Raja, Syed/Sharifah, Wan, Nik, Megat, Dayang…) are regulated and registered by the National Registration Department and "must appear in the National Registration Identity Cards (NRIC), passports as well as all official documents" — [Wikipedia: Malay names](https://en.wikipedia.org/wiki/Malay_names)
- NRD rule reported in 2018: "Abd" and "Mohd" banned, and no name longer than 80 letters — [FMT headline, 28 Sep 2018 (via search result)](https://www.freemalaysiatoday.com/category/nation/2018/09/28/nrd-bans-abd-and-mohd-and-any-name-longer-than-80-letters)
- On 5 May 2026 the NRD Penang office (JPNPP) reminded parents that "Mohd" is no longer accepted: "The name should be written in full as Mohamad, Muhamad, or Muhammad". "Abd" and "Mohd" must be spelled out as "Abdul" and "Muhammad". Many adults still carry "Mohd" on their ICs — [SAYS, published 6 May 2026](https://says.com/my/news/mohd-can-no-longer-be-used-must-be-spelled-out-in-full-jpn)
- NRD guidelines (Aug 2026): registered names must not exceed **80 characters including spaces**. Single letters, numbers and honorific titles (Tan Sri, Datuk, Tun, Haji, Dr) are not allowed in names. Hereditary titles (Tengku, Engku, Megat, Syed, Sharifah, Nik) are allowed only if inherited through the father in a legitimate marriage. a/l and a/p (Indian "son/daughter of") are not compulsory — [The Star, 8 Aug 2026](https://www.thestar.com.my/metro/metro-news/2026/08/08/guideline-for-registering-childrens-names-in-msia)
- NRD has received 1,575 applications to *shorten* names since 2024 — [Malay Mail, 29 May 2026 (search-result snippet)](https://www.malaymail.com/amp/news/malaysia/2026/05/29/nrd-receives-over-1500-applications-to-shorten-names-since-2024/221871)
- Malaysian real-world variant attested: "Mohd Faizol Hussien" (ie for ei) — [Wikipedia: Hussein](https://en.wikipedia.org/wiki/Hussein); "Muhamad Radhi Mat Din", "Muhamad Khalid Jamlus" (single-m Muhamad) — [Wikipedia: Muhammad (name)](https://en.wikipedia.org/wiki/Muhammad_(name))
- Indonesia: Muslim names "usually contain some variation of 'Muhammad' and other Arabic names (with no apparent consensus on transliteration rule)". Popular Arabic names include Muhammad, Ahmad, Arief, Akbar, Reza, Aisyah, Nur, Nabila, Zahra. Localized forms: Betawi Leman (Sulaiman), Rojak (Razak); Javanese Kanapi (Hanafi), Marpuah (Marfu'ah), Ngabdurohman (Abdurrahman), Sarip (Sharif), Slamet (Salamah), Solikin (Salihin); scholar names Ghozali, Romli, Syafi'i. Old orthography "Soe" corresponds to modern "Su" (Soeprapto/Suprapto). Many Javanese are mononymous (Sukarno, Suharto). Examples: Teuku Muhammad Hasan, Mohammad Hatta — [Wikipedia: Indonesian names](https://en.wikipedia.org/wiki/Indonesian_names)

### Inferences
- **Abbreviation expansion table (bidirectional, for matching):** Mohd/Mohd./Muhd/Muhd./Md/Md./Mhd/M. → {Muhammad, Mohamad, Mohammad, Mohammed, Muhamad, Mohamed}; Abd/Abd. → Abdul; B./Bin → bin; Bt./Bte./Bint./Binti → binti; Ct → Siti; Nor/Noor/Nur/Nurul; Syed/Sayed/Said ↔ Sayyid; Sharifah/Syarifah; Sk/SK ↔ Sheikh; Mst/Most ↔ Mosammat.

Pre-1972 Indonesian spelling: oe→u, dj→j, tj→c, j→y, sj→sy, ch→kh.
- In Malay names the patronymic after bin/binti is the father's personal name, not a surname. Matching should support "Given bin Father" ⇄ "Given Father" ⇄ "Given B. Father".

## Q7. Cross-language variant patterns for Arabic-origin names, and the consonant mappings that drive them

### Takeaway
Most variation is predictable from (1) how each language *pronounces* the Arabic letter (Persian/Urdu/Turkish merge ث→s, ذ ض ظ→z, ح→h, and Persian/Turkish و→v), (2) each language's short-vowel system (Arabic a-i-u; Persian a-e-o; Turkish vowel harmony a/e, ı/i, o/ö, u/ü; Bengali o-colouring), (3) the romanization tradition (English th/dh/kh/gh digraphs, French ou, Malay sy), and (4) gemination and article handling. A matcher can build a **phonetic skeleton key** from these merges and then rank candidates by edit distance.

### Cited Findings
- Hussein variant list: Ḥusayn (EI2/EI3; "Ḥusain" in EI1), Hussein, Hossein/Hosayn/Ḥosayn (Persian), Hussain/Hossain (Indo-Aryan), plus "Husên, Husejin, Husejn, Husain, Hisên, Hussain, Husayin, Hussayin, Hüseyin, Xussein, Hüseyn, Husseyin, Huseyn, Hossain, Hosein, Houssein, Husseyn, Usain" — [Wikipedia: Hussein](https://en.wikipedia.org/wiki/Hussein)
- Uthman is "also spelled Othman" and "transliterated as Osman or Usman, particularly when the name occurs in languages which either have no /θ/ sound or where the character ث is pronounced differently, such as Persian, Bosnian, Turkish, and Urdu" — [Wikipedia: Uthman (name)](https://en.wikipedia.org/wiki/Uthman_(name))

### Inferences
- **Phonetic skeleton key for matching** (computed after Latin normalization: lowercase, strip diacritics, drop ' ’ ʿ ʾ - space):
  1. Sibilant/dental folding: th, ts, s, ss → `S` (Uthman/Usman/Utsman/Osman). Treat th as ambiguous between `S` and `T`, and score both. Keep sh separate. dh, dz, z, and d-before-vowel in Arabic-style forms of ض/ذ (Diya/Ridha) → `Z`, scored as a weaker match than an exact `Z`. Keep zh (ژ) separate from z.
  2. q, k, gh, g(h) before vowel → `K` class (Qadir/Kadir/Ghader/Gadir), with g alone kept separate (Gul).
  3. kh, h-initial-after-Turkish, x → `X` (with h ↔ kh weaker match).
  4. w ↔ v → `V`; ou/oo/u/o → `U`; ee/i/y (vocalic) → `I`; ey/ei/ay/ai/ai → `AI`; e ↔ a ↔ i ↔ o ↔ u treated as low-cost substitutions (unvoweled source).
  5. Double consonants → single.
  6. Article/compound normalization: (abd|abdu|abdul|abdel|abdol|abdur|abdus|abdun|abduz|abd al|abd-al|abd el|abd-ol) + root → `ABD+root`; (ud|ad|al|ul|ol|od|ed|el|-)din/deen → `+DIN`; (u|o|a)llah|ulla|ollah → `+ALLAH`.

  Then rank by Jaro-Winkler/Levenshtein on the skeleton plus a token-set comparison.

## Q8. Unicode issues: ی/ي/ى, ک/ك, Urdu ہ/ھ/ۃ/ے, ZWNJ, digits

### Takeaway
The same visible Persian, Urdu or Pashto name can be encoded with different code points, depending on the keyboard (Arabic vs Persian vs Urdu), OCR, or PDF extraction (presentation forms). A romanizer must (1) normalize for *matching* (fold yeh/kaf/heh variants, strip harakat and tatweel, NFKC presentation forms, handle ZWNJ), yet (2) keep the distinctions needed for *romanization* (Urdu ے = e/ai, ھ = aspiration, ہ vs ه, Pashto ۍ/ې). ICAO's MRZ table assigns distinct codes to each variant, which confirms they are distinct characters in identity documents.

### Cited Findings
- Lucene's PersianNormalizer (used in search engines) maps FARSI_YEH U+06CC and YEH_BARREE U+06D2 → YEH U+064A; KEHEH U+06A9 → KAF U+0643; HEH_YEH U+06C0 and HEH_GOAL U+06C1 → HEH U+0647; and removes HAMZA_ABOVE U+0654 (needed for heh + hamza) — [Lucene.NET PersianNormalizer.cs](https://svn.apache.org/repos/asf/lucene.net/trunk/src/contrib/Analyzers/Fa/PersianNormalizer.cs)
- Persian, Arabic, Urdu and Kurdish share look-alike characters with different code points (ك U+0643 vs ک U+06A9; ي U+064A vs ی U+06CC). Without normalization, the same word typed on Arabic vs Persian keyboards will not match in search. Wikimedia's search had to fold them — [Wikimedia Phabricator T72899 (search-result summary)](https://phabricator.wikimedia.org/T72899)
- ICAO MRZ codes (Doc 9303-3 §6 table C) distinguish: ك K vs ک XKK; ي Y vs ی (farsi yeh) XYA vs ى (alef maksura) XAY vs ے (yeh barree) XYB vs ۍ (yeh with tail) XXY vs ې Y; ه H vs ہ (heh goal) XXG vs ھ (heh doachashmee) XDO vs ۀ (heh with yeh above) XYH vs ۂ (heh goal with hamza) XGE; ة XTA/XAH vs ۃ (teh marbuta goal) XTG; ن N vs ں XNN vs ڼ XXN; گ XGG vs ګ XXK; tatweel U+0640 and all harakat (U+064B–0652, U+0670) "not encoded" — [ICAO Doc 9303-3](https://www.icao.int/sites/default/files/publications/DocSeries/9303_p3_cons_en.pdf)
- ICAO also lists the Unicode code points used for MRZ derivation (e.g. محمد = 0645+062D+0645+062F) and notes that in Persian "his name is usually spelt with a final Persian 'yeh' (ى)" vs the Arabic yeh (ي) — [ICAO Doc 9303-3 App. B](https://www.icao.int/sites/default/files/publications/DocSeries/9303_p3_cons_en.pdf)
- Urdu ه has "two distinct shapes in Urdu: ہ / ه and ھ". The latter marks aspiration after b, ch, d, ḍ, j, k, p, ṙ, t, ṭ. The character ے is used only word-finally — [UNGEGN WGRS Urdu](https://www.eki.ee/wgrs/rom1_ur.pdf)
- BGN/PCGN Urdu encodes ہ as U+06C1 (separately from ه U+0647) and ھ as U+06BE. Aspirates are explicitly letter + U+06BE (e.g. بھ = 0628+06BE) — [BGN/PCGN Urdu](https://assets.publishing.service.gov.uk/media/5ab4e64d40f0b67d64e21540/ROMANIZATION_OF_URDU.pdf)
- BGN/PCGN Pashto: ی/ي both appear (U+06CC/U+064A); ي "y"; ې U+06D0 ē; ۍ U+06CD êy; ئ U+064A+0654 êy. Several Pashto letter forms are "not available with a single Unicode codepoint" in BGN's document, and ځ has a rare variant form (ج with a dot above) with no single code point — [BGN/PCGN Pashto](https://assets.publishing.service.gov.uk/media/5ab4e57ee5274a1aa5933455/ROMANIZATION_OF_PASHTO.pdf)
- BGN/PCGN Persian lists the Persian ye as Unicode **0649**, and gives the numerals with alternate forms ۴/٤ and ۶/٦ (Persian vs Arabic-Indic glyphs) — [BGN/PCGN Persian](https://assets.publishing.service.gov.uk/media/5e1eeaafe5274a4f0f57553a/ROMANIZATION_OF_PERSIAN.pdf)
- ZWNJ (U+200C): "Persian uses this character extensively for certain prefixes, suffixes and compound words. It is necessary for disambiguating compounds from non-compound words, which use a full space." It also appears in Malay Jawi (e.g. ساين‌س "sains") — [Wikipedia: Zero-width non-joiner](https://en.wikipedia.org/wiki/Zero-width_non-joiner)
- ALA-LC Persian turns a separately written affix/compound (ZWNJ or space) into a prime ʹ (Kāẓimʹzādah, mīʹravam). BGN/PCGN joins -ābād, -hā/-ān and Turkic suffixes regardless of the script spacing — [ALA-LC Persian](https://www.loc.gov/catdir/cpso/romanization/persian.pdf); [BGN/PCGN Persian](https://assets.publishing.service.gov.uk/media/5e1eeaafe5274a4f0f57553a/ROMANIZATION_OF_PERSIAN.pdf)
- Unicode blocks: Arabic U+0600–06FF (Arabic-Indic digits U+0660–0669; Extended Arabic-Indic digits U+06F0–06F9, used for Persian and Urdu); Arabic Presentation Forms-A U+FB50–FDFF and -B U+FE70–FEFF — [Unicode Arabic code chart](https://www.unicode.org/charts/PDF/U0600.pdf)

### Inferences
- In this session, text extracted from LoC/BGN PDFs came back as **presentation-form glyphs** (e.g. U+FE9B for ث), and combining diacritics below were lost or detached (U+0324 kept, line-below lost). Pipelines that ingest names from PDFs must NFKC-normalize, and must not trust diacritics in romanized text taken from PDFs.
- Persian keyboard input of Urdu/Pashto names often substitutes ی for ے/ې/ۍ and ه for ہ/ھ. Before romanizing, run a script/language detector (presence of ٹ ڈ ڑ ں ھ ے → Urdu; ټ ډ ړ ږ ښ ځ څ ڼ ې ۍ → Pashto; پ چ ژ گ alone are ambiguous between Persian, Urdu and Pashto).
- Store both the raw string and the normalized key, and keep the **ICAO MRZ X-code string as a lossless canonical identifier**: it is defined for every Persian/Urdu/Pashto letter and is ASCII-only.
